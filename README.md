# Кинозал — агент по раздачам kinozal.me

Локальный веб-агент, который по просьбе в чате находит раздачи на kinozal.me,
скачивает `.torrent`, ставит его в Transmission и умеет **следить за новыми
сериями** параллельно по любому числу задач.

Сайт: `https://<IP-мака>:8000/` (проброс порта — снаружи; локально
`https://127.0.0.1:8000/`).

---

**Агент независим от интерфейса.** Всё поведение — в `core/agent.py`; он отдаёт
объекты `Turn` с кнопками `Action`. Веб их рисует, но точно так же их сможет
отрисовать Telegram-бот: `agent.handle_message(session, text, mode)`,
`agent.handle_action(session, kind, payload)`, `agent.list_tasks()`,
`agent.cancel_task(id)`. Проверяется это тем, что `core/cli.py` работает без
сервера и без браузера.

## 2. Быстрый старт

```bash
cd ~/torrent-checker
scripts/run.sh start          # поднимет шлюз и сайт, выпустит сертификат
scripts/run.sh status         # состояние, адреса, проверка /health
scripts/run.sh logs           # последние строки логов
scripts/run.sh stop|restart
scripts/run.sh cert           # перевыпустить самоподписанный сертификат
```

Адрес: **https://<IP-мака>:8000/** — IP задаётся в `.env` (`SITE_TLS_NAMES`,
`PUBLIC_URL`), пароль входа — `SITE_PASSWORD`.
Браузер один раз предупредит о самоподписанном сертификате — это ожидаемо.

Зависимости (уже установлены в `.venv`):

```bash
.venv/bin/pip install -r requirements.txt
cd mcp/kinozal-mcp && npm install && npm run build
```

## 3. Как это работает

### 3.1 Два процесса

| Процесс | Порт | Зачем |
|---|---|---|
| `web.app` (uvicorn, HTTPS) | `0.0.0.0:8000` | сайт; слушает все интерфейсы, иначе проброс порта бесполезен |
| `services.gate_service` | `127.0.0.1:8123` | обход Cloudflare; наружу не выставляется |

### 3.2 Cloudflare — главная сложность kinozal.me

`browse.php`, `details.php`, `login.php`, `download.php` закрыты managed-challenge
Cloudflare: `curl`, `httpx`, `node-fetch`, `curl_cffi` с любым `impersonate` и
headless-браузеры получают `403` и страницу «Just a moment…». Проходит только
**настоящий Chrome**, который исполняет JS-задачу.

Отсюда схема шлюза (`services/cf_gate.py`):

1. Chrome запускается через CDP (`nodriver`), окно сдвинуто за экран
   (`--window-position=-2400,-2400`), профиль — `data/chrome-profile`.
2. Chrome проходит challenge и получает cookie `cf_clearance`.
3. Дальше по сайту ходит `curl_cffi` с этим cookie и User-Agent браузера —
   десятки миллисекунд вместо секунд.
4. Протух `cf_clearance` → шлюз видит `403`/`cf-mitigated`, будит браузер,
   проходит challenge заново и повторяет запрос.
5. Вход на трекер (`POST /takelogin.php`) делает **браузер**: этот POST
   Cloudflare у обычного клиента отбивает.

Проверено, что headless не работает вообще (`GATE_HEADLESS=1` — не поможет),
поэтому по умолчанию окно «настоящее», но за пределами экрана.

### 3.3 MCP

Взят [tokezooo/kinozal-mcp](https://github.com/tokezooo/kinozal-mcp) и лежит
форком в `mcp/kinozal-mcp`. Изменения:

* `BASE_URL` → `https://kinozal.me` (зеркало из задачи);
* транспорт: вместо `node-fetch` напрямую — через шлюз (`KINOZAL_GATE_URL`),
  потому что иначе Cloudflare не пускает;
* `download_torrent`: логин выполняет шлюз, файл приходит в base64 и
  проверяется на bencode (иначе вместо `.torrent` сохранилась бы HTML-страница
  «Вход»); если трекер вместо файла отдал страницу с уведомлением (например,
  исчерпан дневной лимит торрент-файлов), из неё достаётся фраза-причина;
* новый инструмент `get_file_list`: список файлов раздачи со страницы
  (AJAX `get_srv_details.php?action=2`). На kinozal.me число `.torrent`
  в сутки ограничено, а состав файлов нужен уже для карточки — поэтому
  карточка и выбор серий показываются без траты лимита, а `.torrent`
  качается только когда человек нажимает «Скачать»;
* разбор страницы раздачи переписан под разметку `.me` (шапка блоками,
  техданные из `#tabs`, размер/сиды/даты из бокового списка).

Инструменты: `search_torrents`, `get_torrent_details`, `get_file_list`,
`download_torrent`. Агент общается с ними по MCP-протоколу через stdio
(`core/mcp_client.py`), поэтому второй трекер добавляется как второй MCP-сервер,
без правок ядра.

### 3.4 Модель

DeepSeek `deepseek-flash` (DeepSeek-V4.1-Flash), ключ в `.env`.
Размышления выключены параметром `"thinking": {"type": "disabled"}` — без него
модель возвращает `reasoning_content` и тратит на него время.

Модель делает две вещи:
1. **разбирает запрос** в строгий JSON (название, качество, озвучка, сезон,
   серия, период, «качать сразу или только сообщать»);
2. **формулирует тексты** ответов.

Выбор конкретной раздачи делают правила (`core/matching.py`), а не модель:
одинаковый запрос даёт одинаковый результат, а «4к» не превращается в что попало.

### 3.4-бис Куда качаем: только внешний диск

Загрузки всегда идут на внешний SSD. Путь задаётся `TRANSMISSION_DOWNLOAD_DIR`
(по умолчанию `/Volumes/EAGET/torrents`) и передаётся **в каждом** `add_torrent`
явно — правка настроек в самом Transmission не сможет увести файлы на системный
раздел. Дополнительно агент один раз за процесс переводит на этот диск общие
настройки клиента (`download_dir` и `incomplete_dir`), чтобы торренты,
добавленные руками, тоже ложились туда.

Перед постановкой в очередь проверяются две вещи:

1. **Диск смонтирован.** Если `/Volumes/…` нет, раздача не ставится: агент
   говорит «внешний диск не подключён» вместо того, чтобы молча залить 40 ГБ
   на внутренний. Проверка — именно `ismount`, а не «каталог существует».
2. **Места хватает.** Точный размер берётся из `.torrent` (bencode:
   `info.length` или сумма `info.files[]`), к нему добавляется резерв
   `TRANSMISSION_MIN_FREE_GB` (по умолчанию 5 ГБ). Не хватает — в чат приходит
   сообщение вида «нужно 36,8 ГБ + резерв 5 ГБ, свободно 12,3 ГБ (не хватает
   29,5 ГБ)», раздача **не** попадает в очередь и **не** запоминается как
   скачанная, а под сообщением есть кнопка **«Поставить в очередь»** — она
   повторяет попытку с уже скачанным `.torrent`, без повторного поиска.
   То же уведомление уходит в центр уведомлений, в систему и в Web Push.

Свободное место видно заранее: в карточке подтверждения («Качать буду на
«EAGET», свободно 223,5 ГБ из 223,5 ГБ») и в панели «Служебное».

### 3.4-тер Контекст переписки и уточнения

Модель разбирает запрос не в вакууме: ей передаётся **скользящее окно** из
последних `CONTEXT_MESSAGES` сообщений (по умолчанию **20**) и состояние текущей
задачи. Поэтому уточнение работает словами:

```
вы:    Тед Лассо
агент: В раздаче 10 серий — какую качать?  [Серия 1] … [Серия 10]
вы:    нет, нужен 4K
агент: Уточнил: качество: 2160p. Смотрю по уже найденным раздачам.
```

Что происходит под капотом:

* окно = последние 20 сообщений сессии (длинные ответы агента обрезаются до 400
  символов), плюс строка вида «Текущая задача: «Тед Лассо», состояние
  awaiting_choice, параметры: title=…, quality=…»;
* модель возвращает разобранные параметры **и** флаг `refine` — «это уточнение,
  а не новая задача»;
* решение всё равно проверяется правилами (`_is_refinement`): сообщение без
  названия («нужен 4K», «7 серия», «не то») — уточнение к активной задаче; то же
  название — тоже уточнение; **другое название — новая задача**;
* уточнение сливается с параметрами активной задачи (`quality`, `voice`,
  `season`, `episode_from`, `year`, `title`), задача помечается «Уточнил: …»;
* если название не менялось — **нового поиска нет**: перебираются уже найденные
  раздачи (быстро и без лишних запросов к трекеру); если название поменялось —
  поиск идёт заново.

Активной считается незакрытая задача этой сессии в состоянии
`awaiting_choice`, `awaiting_confirm`, `not_found` или `awaiting_setup`. Ответы
на вопросы («что ты умеешь?») тоже получают контекст — последние 10 сообщений.

### 3.5 Жизненный цикл задачи

```
поиск → выбор варианта → подтверждение → скачивание → готово
   │           │                 │
   │           └── кнопки «1080p», «720p», «LostFilm»… (из того, что реально есть)
   └── ничего не найдено → «Сделать периодической»

периодическая: подтверждение («качать сразу» / «только сообщать») → мониторинг
```

Состояния: `searching`, `awaiting_choice`, `awaiting_confirm`, `downloading`,
`monitoring`, `done`, `not_found`, `failed`, `cancelled`.

Если качество или озвучка не названы, агент смотрит, что реально есть на
трекере, и предлагает выбрать **из имеющегося** (одно значение подставляет сам,
чтобы не спрашивать зря). Если ничего нет — честно говорит и предлагает сделать
задачу периодической.

### 3.5-тер Опечатки и «возможно, вы имели в виду»

Трекер ищет по всем словам запроса, поэтому «битва экстрасенсов реванш» даёт
ноль, хотя на трекере есть «Экстрасенсы. Реванш». А иногда наоборот: находит
«Битва экстрасенсов» — другой сериал, и пользователь рискует скачать не то.

Агент разбирает такие запросы в два шага (`core/suggest.py`):

1. **Укороченные варианты запроса.** Из исходного текста строятся скользящие
   окна по словам («экстрасенсов реванш»), варианты без первого и без последнего
   слова, самое длинное слово. Если исходный запрос ничего не нашёл — они ищутся
   на трекере.
2. **Похожесть названий.** Найденное сравнивается с исходным запросом:
   отношение последовательностей, покрытие слов (с учётом форм:
   «экстрасенсов» ≈ «экстрасенсы») и отдельно покрытие «хвоста» запроса — в
   названиях важные слова обычно в конце. Лишние слова в названии дают штраф.

Результат виден в двух случаях:

* **ничего не нашлось** — «По запросу «…» на kinozal.me ничего не нашлось.
  Возможно, вы имели в виду: 1. Экстрасенсы. Реванш …» и кнопки с названиями
  (плюс «Искать как написал» и «Следить за этим названием»);
* **нашлось, но не то** — в карточке появляется предупреждение «⚠ Название
  совпало не точно. Возможно, вы имели в виду…». Проверка идёт по **исходному
  тексту пользователя**: если в нём были значимые слова, которых нет в найденном
  названии («реван»), значит поиск нашёл похожее, но не тот сериал.

Нажатие на название перезапускает поиск уже по нему — без ручного ввода.
Укороченные варианты запрашиваются только при подозрении на неточность, поэтому
обычный поиск не становится медленнее.

### 3.5-бис Что именно качать: серия, сезон или фильм

Сезон на трекере часто лежит одной раздачей из 10–20 файлов. Поэтому «скачать»
идёт в два шага:

1. **Поиск и уточнение.** Агент ищет по названию и предлагает выбрать
   качество и озвучку — только из того, что реально есть под остальные условия.
   Варианты считаются **с учётом уже заданных условий**: если в 4-м сезоне нет
   720p, кнопки «720p» не будет (раньше агент предлагал его, а после нажатия
   честно отвечал «ничего не подошло»). Кнопки сгруппированы подписями
   **Качество**, **Озвучка**, **Серии** — видно, что к чему относится.

   Если выбранное не подходит, агент не повторяет тот же список, а показывает
   доступное **при остальных условиях** и даёт кнопки «Без учёта качества» /
   «Без учёта озвучки».

3. **Выбор серий.** Как только качество и озвучка определены, агент забирает
   `.torrent` (он маленький) и показывает настоящий состав раздачи: кнопки
   `Серия 1 · 3,3 ГБ` … `Серия 8`, причём **выбор множественный** — отметьте
   несколько галочками. Кнопка сразу показывает количество и сумму
   (`Скачать выбранные (3 · 10,8 ГБ)`), а на карточке видны свободное место и
   каталог. Нажатие **сразу ставит в Transmission** — второго вопроса «поставить
   в очередь?» нет.
   Если серия названа в запросе или текстом в чате («только 3 серия»),
   этот шаг пропускается.

4. **Карточка подтверждения.** Она нужна, только когда агент выбрал раздачу сам
   (один файл, фильм) или когда вы взяли **другой вариант** из списка
   («Взять вариант 2»). Это полная информация перед постановкой в очередь:

   ```
   Раздача: Тед Лассо (4 сезон: 1-10 серии из 10) / Ted Lasso / 2026 / ПМ (NewComers) / WEB-DL (1080p)
   • Качество: 1080p, WEB-DL
   • Озвучка: ПМ (NewComers), СТ
   • Сезон 4, серия 7
   • Что качаем: 1 файл — Ted.Lasso.S04E07.1080p.WEB-DL.NewComers.mkv
   • Вес выбранного: 3,3 ГБ
   • Вес всей раздачи: 36,8 ГБ
   • Диск «EAGET»: свободно 204,9 ГБ из 223,5 ГБ (резерв 5 ГБ)
   • Места хватает
   • Куда: /Volumes/EAGET/torrents
   ```

   Кнопки: `Поставить в Transmission`, `Скачать весь сезон` (если выбрана серия),
   `Отмена`.

Если серия названа прямо в запросе («… 7 серия»), шаг выбора пропускается —
сразу показывается карточка с этой серией. Если такой серии в раздаче нет,
агент честно говорит об этом и предлагает выбрать из имеющихся.

**Как качается одна серия.** В Transmission передаётся `files_wanted` с индексами
файлов этой серии (видео плюс субтитры того же эпизода), остальные помечаются
ненужными — Transmission качает 3,3 ГБ вместо 36,8 ГБ. Проверено на реальной
раздаче: из 10 файлов выбран один, и в памяти агента сохраняется именно серия 7
(а не «пачка 1–10»), иначе следующая проверка решила бы, что серии 8–10 уже есть.

Вес берётся не из строки на трекере, а из самого `.torrent` (bencode), поэтому
это точное число байт — по нему же считается, хватает ли места на диске.

### 3.6 Память «что уже скачано» и «новая серия»

Скачанное пишется в таблицу `downloads` (id раздачи, сериал, сезон, серия,
качество, озвучка, дата заливки). По ней:

* уже скачанная раздача не предлагается и не качается повторно;
* «новая серия» = раздача, которой раньше не было, **и** её номер серии выше
  максимального известного в том же сезоне (для фильмов — по дате заливки).

Многосезонные пачки («1–4 сезоны: 1–44 серии из 44») в нумерацию не попадают:
в них счёт сквозной, и «44» ничего не говорит о четвёртом сезоне — иначе новая
11-я серия считалась бы уже скачанной. При создании периодической задачи
фиксируется «базовая линия» (что есть сейчас), поэтому первая проверка не
присылает уведомление про все 30 раздач сразу.

### 3.7 Периодические задачи

Периодическая задача — это сохранённое намерение: «проверяй вот это и делай вот
так». Она живёт независимо от переписки, у неё свой интервал и свой режим.

**Как заводится.**

1. Кнопка **«Периодически»** + запрос. Модель разбирает его в параметры:
   название, сезон, `episode_from` («начиная с третьей»), качество, озвучку,
   интервал (`interval_minutes`) и `auto_download` — надо ли качать сразу.
2. Агент сразу ищет по трекеру и показывает, что есть сейчас.
3. Карточка подтверждения спрашивает режим двумя кнопками:
   **«Качать сразу и сообщать»** или **«Только сообщать»**. Если в запросе было
   «качай сразу», агент это учитывает и пишет об этом в карточке.
4. При подтверждении фиксируется **базовая линия**: какие серии уже лежат на
   трекере. Они новыми не считаются — иначе первая же проверка прислала бы
   уведомление про весь сезон.
5. Дальше задача в состоянии `monitoring`, `next_check_at` = сейчас + интервал.

**Что происходит на каждой проверке** (шедулер просыпается раз в 20 секунд и
берёт задачи, у которых наступило время; каждая задача — отдельная корутина,
они не мешают друг другу и лимита на их число нет):

1. Поиск по трекеру и фильтрация по параметрам задачи.
2. Для каждой найденной раздачи считается, **новая ли она**:
   * сериал с одним сезоном — сравнивается **номер серии**: раздача новая,
     если в ней есть серия ≥ той, которую ждём;
   * пачка на несколько сезонов — по дате заливки (нумерация там сквозная);
   * фильм/музыка/книга — по дате размещения.
3. «Какую серию ждём» (`next_episode`) = `max(episode_from,
   максимальная скачанная серия + 1)`. Поэтому задача «качай новые, начиная с
   третьей» после третьей ищет четвёртую, а не третью повторно.
4. Если нового нет — тишина (в журнал проверок пишется «0 новых»).
5. Если есть:
   * **режим «качать сразу»** — `.torrent` перекачивается (на трекере та же
     раздача обновляется новыми выпусками, старый файл уже не содержит нужную
     серию), из него выбираются **только новые серии**, они ставятся в
     Transmission, и приходит уведомление о том, что сделано;
   * **режим «только сообщать»** — приходит уведомление со списком находок и
     кнопками «Скачать N»; ничего не качается, пока пользователь не нажмёт.

**Почему номер серии, а не id раздачи.** На kinozal одна и та же раздача
обновляется по мере выхода выпусков: «3 сезон: 1-2 выпуски из 14» → «1-3» →
«1-4». Если считать «новое» по id, второй выпуск никогда бы не скачался.
Поэтому приоритет у номера серии, а id служит только для неэпизодического
контента (фильмы, музыка).

**Что именно скачивается из пачки.** Если в раздаче 14 файлов и нужна третья
серия, в Transmission передаётся `files_wanted` с индексом одного файла:
качается 1,9 ГБ вместо 26 ГБ. Если появились сразу две новые серии — обе.
Имя серии определяется по имени файла: `S03E07`, `4x07`, «серия 7», «выпуск 7»
и ведущий номер (`01. Название.avi`).

**Память и удаление файлов.** Запись о скачанном делается **после** постановки
в Transmission и защищена от ошибок: если запись почему-то не удалась, торрент
остаётся в очереди, а в журнале отладки появляется «скачанное не записано в
память». Так не бывает «торрент в Transmission есть, а агент про него не знает»
— именно этот случай однажды случился из-за падения разбора плана серий.

 Каждая скачанная серия записывается отдельной
строкой (раздача + сезон + серия), поэтому одна и та же раздача может дать
несколько записей. Из этой памяти и считается `next_episode`.

Удаление файлов **не стирает память**: запись помечается удалённой
(`deleted_at`), пропадает из списка «Скачано на диск», но продолжает считаться
прогрессом. Поэтому если вы посмотрели третью серию и удалили её, чтобы не
занимать место, задача «качай новые, начиная с третьей» продолжит с четвёртой, а
не скачает третью заново. Если ту же серию скачать заново вручную — запись
«оживает», дубликата не появляется.

**Управление.** В картотеке у задачи есть «Проверить сейчас» и «Отменить».
Отмена переводит задачу в `cancelled`, проверки прекращаются.



Каждая задача живёт в своей корутине (`_scheduler_loop` → `_run_check_isolated`),
падение одной не влияет на другие, лимита на количество нет. Шедулер просыпается
раз в 20 секунд и берёт задачи, у которых наступило `next_check_at`.

Найдено новое:
* режим «только сообщать» — уведомление + кнопки «Скачать 1/2/3», задача
  продолжает жить;
* режим «качать сразу» — скачивает (до 3 новых за раз), ставит в Transmission,
  сообщает.

Уведомления идут по трём каналам сразу (`core/notify.py`, `core/push.py`):
центр уведомлений в интерфейсе (SSE), системные уведомления macOS, Web Push.

### 3.7-тер Видно процесс загрузки

Transmission RPC не умеет присылать события — только отвечать на запросы.
Поэтому агент опрашивает прогресс сам (`Agent.refresh_progress`, раз в 5 секунд),
и задача **не прыгает в завершённые сразу** после постановки в очередь:

* состояние `downloading` — пока файл не дошёл до 100%;
* в карточке задачи и в списке «Скачано на диск» виден прогресс-бар и подпись
  `42,5% · 1 МБ/с · осталось 10 мин · 1,7 ГБ из 4 ГБ`;
* когда загрузка закончилась — задача уходит в «Завершённые», в чат приходит
  «Скачано: «…» (3,7 ГБ)», уходит уведомление в центр/систему/Web Push;
* если раздачу удалили из очереди вручную — задача тоже закрывается, а не висит.

Объём считается по **выбранным файлам** (`size_when_done`), а не по всей
раздаче: качаем одну серию — видим «из 3,7 ГБ», а не «из 29 ГБ».

### 3.7-бис Журнал отладки

В «Служебном» есть кнопка **«Журнал отладки»**. Она открывает окно с тем, что
агент делал на самом деле — не HTTP-логи, а суть:

| Категория | Что видно |
|---|---|
| `llm` | запрос к модели и её ответ: параметры разбора, тексты, вызовы инструментов, токены, время |
| `mcp` | какой инструмент трекера вызван, с какими аргументами и что вернул (сколько символов, текст ответа) |
| `gate` | запросы к kinozal.me через шлюз: адрес, статус, прошёл ли через браузер или curl_cffi, отказы Cloudflare |
| `transmission` | постановка в очередь, каталог, размер, отказы «не хватает места» |
| `agent` | что модель поняла из запроса, сколько раздач нашлось, что выбрано, результат проверки периодической задачи |
| `log` | предупреждения и ошибки из логов модулей |

В окне есть фильтры по категориям, раскрытие подробностей по клику, автообновление
раз в 4 секунды, кнопки «Обновить», «Скопировать» (в буфер обмена простым текстом)
и «Очистить». Длинные значения обрезаются, чтобы список оставался читаемым.

Журнал **общий для процессов**: шлюз Cloudflare работает отдельным процессом, но
пишет в тот же файл `data/debug.jsonl`, поэтому его события видны в интерфейсе
наравне с вызовами модели. Файл ограничен последними 3000 событиями, лежит в
`data/` (не в репозитории) и его можно удалить в любой момент — на работу агента
это не влияет. Ключи и пароли в журнал не попадают никогда.

### 3.7-тер Удаление раздачи вместе с файлами

В картотеке, в списке «Скачано», у каждой раздачи есть кнопка **«Удалить»**.
Она сначала спрашивает подтверждение («файлы стираются насовсем, минуя
корзину»), и только по кнопке «Удалить навсегда» делает три вещи:

1. убирает раздачу из очереди Transmission (без его собственного удаления
   данных);
2. стирает файлы раздачи и её недокачанную часть с диска;
3. удаляет `.torrent`-файл и запись из памяти агента (скачанное больше не
   считается скачанным).

**Почему не штатное удаление Transmission.** На macOS Transmission перемещает
данные в `.Trashes` на том же томе, и место не освобождается, пока корзину не
очистят руками. Поэтому данные стирает сам агент — обычными `os.remove` и
`shutil.rmtree`, которые корзину не используют. Проверено на реальной раздаче:
после удаления свободное место на диске вернулось сразу, а `.Trashes` не вырос.

**Защита от ошибок.** Пути приходят из Transmission RPC, поэтому каждый путь
приводится к реальному (`realpath` — снимает `..` и симлинки) и обязан лежать
внутри разрешённых корней: каталога загрузок, его `.incomplete` и папки
torrent-файлов. Сам корень удалить нельзя. Всё, что не прошло проверку, не
удаляется и попадает в отчёт как «не тронуто (вне разрешённых папок)».

Отдельно решена гонка: Transmission убирает раздачу не мгновенно, и файл мог
дописаться уже после удаления — папка появлялась снова. Теперь агент ждёт
исчезновения раздачи из очереди, а затем ещё до трёх раз дочищает остатки.

### 3.7-кватер Место на диске: занято, наши файлы и корзина

В «Служебном» диск показан тремя строками, и это не избыточность:

```
диск          EAGET · свободно 204,9 ГБ из 223,5 ГБ
занято        18,6 ГБ · наши файлы 0 Б
не наши файлы 18,6 ГБ — чужие данные или корзина диска
```

Зачем: macOS в Finder не показывает содержимое `.Trashes` на внешнем томе, а
Transmission при штатном удалении перемещает данные именно туда. В итоге место
занято, диск «пуст», и цифра выглядит враньём. Теперь видно, сколько занято
всего, сколько из этого — загрузки агента и torrent-файлы, и что остаток
приходится на что-то ещё. Место вернётся после **«Очистить корзину»** в Finder
(она чистит и корзины томов) или командой
`sudo rm -rf /Volumes/<диск>/.Trashes/501/*`.

Наши файлы считаются отдельно (`core/storage_target.dir_size`) с ограничением по
времени: обход 200 ГБ ради строчки в интерфейсе недопустим, поэтому при
превышении бюджета значение помечается как приблизительное (`≈`).

### 3.8 Интерфейс

Старая киноплёнка: сепия, зерно, мерцание проектора, перфорация по краям,
винетка. Без внешних шрифтов и картинок — всё рисуется CSS, поэтому работает и
офлайн, и на телефоне.

Декоративные «царапины» живут только в полосе перфорации по краям экрана
(`mask-image` вырезает середину): раньше они шли вертикальными линиями через
всю страницу и попадали прямо на текст сообщений — читалось как случайная
полоса. На телефоне, где переписка занимает всю ширину, царапины выключены.

* две кнопки режима — **Разово** и **Периодически**;
* картотека слева (на телефоне — выдвижная панель) из трёх разделов, и это
  **разные вещи**:
  * **В работе** — активные задачи: ищут, ждут подтверждения, следят за новым;
  * **Завершённые** — задачи, которые закончились: готово, отменено, не найдено,
    ошибка (история решений, а не файлов);
  * **Скачано на диск** — то, что реально лежит в Transmission и на внешнем
    диске; отсюда же удаление.

  У каждого раздела свой счётчик и своя кнопка **«показать/скрыть»**, состояние
  запоминается в браузере. Пустой список показывает заглушку («активных задач
  нет») и от этого не схлопывается: у кнопки всегда есть видимый эффект. У
  каждой задачи в «В работе» и «Завершённых» есть кнопки «Проверить» и
  «Отменить»;
* колокольчик — киножурнал уведомлений;
* «Доступы» — логин/пароль kinozal и RPC Transmission (пишутся в SQLite и
  перекрывают `.env`, перезапуск не нужен);
* мобильная раскладка с `safe-area-inset` под iPhone.

## 6. Ограничения и что требует внимания

1. **Учётка kinozal.me обязательна.** Без входа сайт вместо `.torrent` отдаёт
   страницу «Вход», и агент честно сообщает об этом в чате. Логин и пароль
   задаются в `.env` (`KINOZAL_USERNAME`, `KINOZAL_PASSWORD`) или прямо в
   интерфейсе: кнопка **Доступы** → «Проверить». Там же видно, принял ли сайт
   пару — трекер отвечает внятно («Неверно указан пароль для имени …»).
2. **Web Push и service worker** требуют доверенного HTTPS: с недоверенным
   сертификатом браузер отказывается регистрировать service worker (в консоли
   «SSL certificate error»), и push не работает. Чтобы включить, сертификат
   проекта добавляется в доверенные один раз на машине, где открывают сайт:

   ```bash
   security add-trusted-cert -r trustRoot -p ssl \
     -k "$HOME/Library/Keychains/login.keychain-db" data/tls/site.crt
   ```

   Три вещи, без которых это не сработает и на них легко наступить:
   сертификат выпускается с `CA:TRUE` (иначе macOS не даст сделать его
   корневым), политика указывается явно (`-p ssl`), а после установки нужен
   перезапуск браузера. Телефону сертификат ставится отдельно (профиль `.crt`
   из `data/tls/`). На этой машине уже сделано — центр уведомлений, системные
   уведомления macOS и Web Push работают все три.
3. **Chrome шлюза — видимый процесс.** Он настоящий (иначе Cloudflare не
   пустит), окно за пределами экрана. Закрывать его вручную не нужно.
4. **Transmission** хранит пароль RPC в своём keychain, поэтому его нужно
   вписать в `.env` (`TRANSMISSION_USERNAME`, `TRANSMISSION_PASSWORD`) или в
   «Доступы». При смене пароля — там же.
5. Сайт слушает `0.0.0.0` и проброшен наружу: держите `SITE_PASSWORD`
   заполненным.
6. **Не коммитьте `.env`.** В нём ключ модели, пароли трекера и RPC. Файл уже
   в `.gitignore`; в репозиторий попадает только шаблон `.env.example` с
   пустыми значениями и без адресов вашей сети.
7. **Если удалять в самом Transmission, данные уходят в корзину.** Штатное
   удаление в Transmission на macOS перемещает файлы в `.Trashes` на том же
   диске, и место освобождается только после очистки корзины (Finder →
   «Очистить корзину»). Кнопка «Удалить» в агенте работает иначе — стирает файлы
   сразу, без корзины.
8. **Правка `.env` требует перезапуска** (`scripts/run.sh restart`): настройки
   читаются один раз при старте. Логины и пароли kinozal/Transmission — другое
   дело, их можно менять на ходу через «Доступы».
