# Кинозал — агент по раздачам kinozal.me

Локальный веб-агент, который по просьбе в чате находит раздачи на kinozal.me,
скачивает `.torrent`, ставит его в Transmission и умеет **следить за новыми
сериями** параллельно по любому числу задач.

Сайт: `https://<IP-мака>:8000/` (проброс порта — снаружи; локально
`https://127.0.0.1:8000/`).

---

## 1. Что внутри

```

├── core/                 ядро агента — БЕЗ веба, БЕЗ HTML (можно подключить бота)
│   ├── agent.py          мозг: состояния задач, поиск, подтверждения, скачивание
│   ├── cli.py            CLI-адаптер (доказательство независимости от UI)
│   ├── config.py         настройки из .env
│   ├── llm.py            клиент DeepSeek (thinking выключен)
│   ├── mcp_client.py     MCP-клиент к kinozal-mcp по stdio
│   ├── parsing.py        разбор названий: качество, озвучка, сезон, серия
│   ├── matching.py       фильтрация, ранжирование, «что такого нового»
│   ├── storage.py        SQLite: задачи, история, «что уже скачано»
│   ├── transmission.py   Transmission RPC
│   ├── notify.py         шина событий + уведомления macOS
│   └── push.py           Web Push (VAPID)
├── services/
│   ├── cf_gate.py        обход Cloudflare: настоящий Chrome + cf_clearance
│   └── gate_service.py   HTTP-обёртка шлюза для MCP-сервера (127.0.0.1:8123)
├── mcp/kinozal-mcp/      форк github.com/tokezooo/kinozal-mcp под kinozal.me
├── web/
│   ├── app.py            FastAPI: только транспорт (вход, JSON, SSE, статика)
│   ├── templates/        index.html, login.html
│   └── static/           style.css (киноплёнка), app.js, sw.js, иконки
├── scripts/run.sh        start/stop/status/логи + автовыпуск сертификата
├── tests/                проверки: правила, MCP, Transmission, интерфейс, шлюз
└── data/                 SQLite, торренты, сертификат, профиль Chrome, логи
```

**Агент независим от интерфейса.** Всё поведение — в `core/agent.py`; он отдаёт
объекты `Turn` с кнопками `Action`. Веб их рисует, но точно так же их сможет
отрисовать Telegram-бот: `agent.handle_message(session, text, mode)`,
`agent.handle_action(session, kind, payload)`, `agent.list_tasks()`,
`agent.cancel_task(id)`. Проверяется это тем, что `core/cli.py` работает без
сервера и без браузера.

## 2. Быстрый старт

```bash
cd ~/torrent-checker
scripts/run.sh start          # поднимет шлюз и сайт, выпустит сертификат
scripts/run.sh status         # состояние, адреса, проверка /health
scripts/run.sh logs           # последние строки логов
scripts/run.sh stop|restart
scripts/run.sh cert           # перевыпустить самоподписанный сертификат
```

Адрес: **https://<IP-мака>:8000/** — IP задаётся в `.env` (`SITE_TLS_NAMES`,
`PUBLIC_URL`), пароль входа — `SITE_PASSWORD`.
Браузер один раз предупредит о самоподписанном сертификате — это ожидаемо.

Зависимости (уже установлены в `.venv`):

```bash
.venv/bin/pip install -r requirements.txt
cd mcp/kinozal-mcp && npm install && npm run build
```

## 3. Как это работает

### 3.1 Два процесса

| Процесс | Порт | Зачем |
|---|---|---|
| `web.app` (uvicorn, HTTPS) | `0.0.0.0:8000` | сайт; слушает все интерфейсы, иначе проброс порта бесполезен |
| `services.gate_service` | `127.0.0.1:8123` | обход Cloudflare; наружу не выставляется |

### 3.2 Cloudflare — главная сложность kinozal.me

`browse.php`, `details.php`, `login.php`, `download.php` закрыты managed-challenge
Cloudflare: `curl`, `httpx`, `node-fetch`, `curl_cffi` с любым `impersonate` и
headless-браузеры получают `403` и страницу «Just a moment…». Проходит только
**настоящий Chrome**, который исполняет JS-задачу.

Отсюда схема шлюза (`services/cf_gate.py`):

1. Chrome запускается через CDP (`nodriver`), окно сдвинуто за экран
   (`--window-position=-2400,-2400`), профиль — `data/chrome-profile`.
2. Chrome проходит challenge и получает cookie `cf_clearance`.
3. Дальше по сайту ходит `curl_cffi` с этим cookie и User-Agent браузера —
   десятки миллисекунд вместо секунд.
4. Протух `cf_clearance` → шлюз видит `403`/`cf-mitigated`, будит браузер,
   проходит challenge заново и повторяет запрос.
5. Вход на трекер (`POST /takelogin.php`) делает **браузер**: этот POST
   Cloudflare у обычного клиента отбивает.

Проверено, что headless не работает вообще (`GATE_HEADLESS=1` — не поможет),
поэтому по умолчанию окно «настоящее», но за пределами экрана.

### 3.3 MCP

Взят [tokezooo/kinozal-mcp](https://github.com/tokezooo/kinozal-mcp) и лежит
форком в `mcp/kinozal-mcp`. Изменения:

* `BASE_URL` → `https://kinozal.me` (зеркало из задачи);
* транспорт: вместо `node-fetch` напрямую — через шлюз (`KINOZAL_GATE_URL`),
  потому что иначе Cloudflare не пускает;
* `download_torrent`: логин выполняет шлюз, файл приходит в base64 и
  проверяется на bencode (иначе вместо `.torrent` сохранилась бы HTML-страница
  «Вход»);
* разбор страницы раздачи переписан под разметку `.me` (шапка блоками,
  техданные из `#tabs`, размер/сиды/даты из бокового списка).

Инструменты остались те же: `search_torrents`, `get_torrent_details`,
`download_torrent`. Агент общается с ними по MCP-протоколу через stdio
(`core/mcp_client.py`), поэтому второй трекер добавляется как второй MCP-сервер,
без правок ядра.

### 3.4 Модель

DeepSeek `deepseek-flash` (DeepSeek-V4.1-Flash), ключ в `.env`.
Размышления выключены параметром `"thinking": {"type": "disabled"}` — без него
модель возвращает `reasoning_content` и тратит на него время.

Модель делает две вещи:
1. **разбирает запрос** в строгий JSON (название, качество, озвучка, сезон,
   серия, период, «качать сразу или только сообщать»);
2. **формулирует тексты** ответов.

Выбор конкретной раздачи делают правила (`core/matching.py`), а не модель:
одинаковый запрос даёт одинаковый результат, а «4к» не превращается в что попало.

### 3.4-бис Куда качаем: только внешний диск

Загрузки всегда идут на внешний SSD. Путь задаётся `TRANSMISSION_DOWNLOAD_DIR`
(по умолчанию `/Volumes/EAGET/torrents`) и передаётся **в каждом** `add_torrent`
явно — правка настроек в самом Transmission не сможет увести файлы на системный
раздел. Дополнительно агент один раз за процесс переводит на этот диск общие
настройки клиента (`download_dir` и `incomplete_dir`), чтобы торренты,
добавленные руками, тоже ложились туда.

Перед постановкой в очередь проверяются две вещи:

1. **Диск смонтирован.** Если `/Volumes/…` нет, раздача не ставится: агент
   говорит «внешний диск не подключён» вместо того, чтобы молча залить 40 ГБ
   на внутренний. Проверка — именно `ismount`, а не «каталог существует».
2. **Места хватает.** Точный размер берётся из `.torrent` (bencode:
   `info.length` или сумма `info.files[]`), к нему добавляется резерв
   `TRANSMISSION_MIN_FREE_GB` (по умолчанию 5 ГБ). Не хватает — в чат приходит
   сообщение вида «нужно 36,8 ГБ + резерв 5 ГБ, свободно 12,3 ГБ (не хватает
   29,5 ГБ)», раздача **не** попадает в очередь и **не** запоминается как
   скачанная, а под сообщением есть кнопка **«Поставить в очередь»** — она
   повторяет попытку с уже скачанным `.torrent`, без повторного поиска.
   То же уведомление уходит в центр уведомлений, в систему и в Web Push.

Свободное место видно заранее: в карточке подтверждения («Качать буду на
«EAGET», свободно 223,5 ГБ из 223,5 ГБ») и в панели «Служебное».

### 3.5 Жизненный цикл задачи

```
поиск → выбор варианта → подтверждение → скачивание → готово
   │           │                 │
   │           └── кнопки «1080p», «720p», «LostFilm»… (из того, что реально есть)
   └── ничего не найдено → «Сделать периодической»

периодическая: подтверждение («качать сразу» / «только сообщать») → мониторинг
```

Состояния: `searching`, `awaiting_choice`, `awaiting_confirm`, `downloading`,
`monitoring`, `done`, `not_found`, `failed`, `cancelled`.

Если качество или озвучка не названы, агент смотрит, что реально есть на
трекере, и предлагает выбрать **из имеющегося** (одно значение подставляет сам,
чтобы не спрашивать зря). Если ничего нет — честно говорит и предлагает сделать
задачу периодической.

### 3.6 Память «что уже скачано» и «новая серия»

Скачанное пишется в таблицу `downloads` (id раздачи, сериал, сезон, серия,
качество, озвучка, дата заливки). По ней:

* уже скачанная раздача не предлагается и не качается повторно;
* «новая серия» = раздача, которой раньше не было, **и** её номер серии выше
  максимального известного в том же сезоне (для фильмов — по дате заливки).

Многосезонные пачки («1–4 сезоны: 1–44 серии из 44») в нумерацию не попадают:
в них счёт сквозной, и «44» ничего не говорит о четвёртом сезоне — иначе новая
11-я серия считалась бы уже скачанной. При создании периодической задачи
фиксируется «базовая линия» (что есть сейчас), поэтому первая проверка не
присылает уведомление про все 30 раздач сразу.

### 3.7 Периодические задачи

Каждая задача живёт в своей корутине (`_scheduler_loop` → `_run_check_isolated`),
падение одной не влияет на другие, лимита на количество нет. Шедулер просыпается
раз в 20 секунд и берёт задачи, у которых наступило `next_check_at`.

Найдено новое:
* режим «только сообщать» — уведомление + кнопки «Скачать 1/2/3», задача
  продолжает жить;
* режим «качать сразу» — скачивает (до 3 новых за раз), ставит в Transmission,
  сообщает.

Уведомления идут по трём каналам сразу (`core/notify.py`, `core/push.py`):
центр уведомлений в интерфейсе (SSE), системные уведомления macOS, Web Push.

### 3.7-бис Журнал отладки

В «Служебном» есть кнопка **«Журнал отладки»**. Она открывает окно с тем, что
агент делал на самом деле — не HTTP-логи, а суть:

| Категория | Что видно |
|---|---|
| `llm` | запрос к модели и её ответ: параметры разбора, тексты, вызовы инструментов, токены, время |
| `mcp` | какой инструмент трекера вызван, с какими аргументами и что вернул (сколько символов, текст ответа) |
| `gate` | запросы к kinozal.me через шлюз: адрес, статус, прошёл ли через браузер или curl_cffi, отказы Cloudflare |
| `transmission` | постановка в очередь, каталог, размер, отказы «не хватает места» |
| `agent` | что модель поняла из запроса, сколько раздач нашлось, что выбрано, результат проверки периодической задачи |
| `log` | предупреждения и ошибки из логов модулей |

В окне есть фильтры по категориям, раскрытие подробностей по клику, автообновление
раз в 4 секунды, кнопки «Обновить», «Скопировать» (в буфер обмена простым текстом)
и «Очистить». Длинные значения обрезаются, чтобы список оставался читаемым.

Журнал **общий для процессов**: шлюз Cloudflare работает отдельным процессом, но
пишет в тот же файл `data/debug.jsonl`, поэтому его события видны в интерфейсе
наравне с вызовами модели. Файл ограничен последними 3000 событиями, лежит в
`data/` (не в репозитории) и его можно удалить в любой момент — на работу агента
это не влияет. Ключи и пароли в журнал не попадают никогда.

### 3.8 Интерфейс

Старая киноплёнка: сепия, зерно, вертикальные царапины, мерцание проектора,
перфорация по краям, винетка. Без внешних шрифтов и картинок — всё рисуется CSS,
поэтому работает и офлайн, и на телефоне.

* две кнопки режима — **Разово** и **Периодически**;
* картотека слева (на телефоне — выдвижная панель): в работе / архив / скачано,
  у каждой задачи кнопки «Проверить» и «Отменить»;
* колокольчик — киножурнал уведомлений;
* «Доступы» — логин/пароль kinozal и RPC Transmission (пишутся в SQLite и
  перекрывают `.env`, перезапуск не нужен);
* мобильная раскладка с `safe-area-inset` под iPhone.

## 4. Настройки (`.env`)

| Переменная | Смысл |
|---|---|
| `SITE_HOST`, `SITE_PORT` | адрес сайта (по умолчанию `0.0.0.0:8000`) |
| `SITE_TLS` | `1` — HTTPS с самоподписанным сертификатом |
| `SITE_TLS_NAMES` | адреса в сертификате (IP мака в домашней сети) |

| `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` | ключ и модель (`deepseek-flash`) |
| `KINOZAL_USERNAME`, `KINOZAL_PASSWORD` | учётка трекера |
| `TRANSMISSION_HOST/PORT/USERNAME/PASSWORD` | RPC Transmission |
| `TRANSMISSION_DOWNLOAD_DIR` | внешний диск для загрузок (`/Volumes/<диск>/torrents`) |
| `TORRENTS_DIR` | папка для `.torrent`-файлов на том же внешнем диске |
| `TRANSMISSION_MIN_FREE_GB` | сколько места обязано остаться после скачивания |
| `GATE_PORT`, `GATE_HEADLESS`, `GATE_PROFILE_DIR` | шлюз Cloudflare |
| `DEFAULT_INTERVAL_MINUTES`, `MIN_INTERVAL_MINUTES` | период проверки по умолчанию и минимум |

Значение из окружения важнее строки в `.env`.

## 6. Ограничения и что требует внимания

1. **Учётка kinozal.me обязательна.** Без входа сайт вместо `.torrent` отдаёт
   страницу «Вход», и агент честно сообщает об этом в чате. Логин и пароль
   задаются в `.env` (`KINOZAL_USERNAME`, `KINOZAL_PASSWORD`) или прямо в
   интерфейсе: кнопка **Доступы** → «Проверить». Там же видно, принял ли сайт
   пару — трекер отвечает внятно («Неверно указан пароль для имени …»).
2. **Web Push и service worker** требуют доверенного HTTPS: с недоверенным
   сертификатом браузер отказывается регистрировать service worker (в консоли
   «SSL certificate error»), и push не работает. Чтобы включить, сертификат
   проекта добавляется в доверенные один раз на машине, где открывают сайт:

   ```bash
   security add-trusted-cert -r trustRoot -p ssl \
     -k "$HOME/Library/Keychains/login.keychain-db" data/tls/site.crt
   ```

   Три вещи, без которых это не сработает и на них легко наступить:
   сертификат выпускается с `CA:TRUE` (иначе macOS не даст сделать его
   корневым), политика указывается явно (`-p ssl`), а после установки нужен
   перезапуск браузера. Телефону сертификат ставится отдельно (профиль `.crt`
   из `data/tls/`). На этой машине уже сделано — центр уведомлений, системные
   уведомления macOS и Web Push работают все три.
3. **Chrome шлюза — видимый процесс.** Он настоящий (иначе Cloudflare не
   пустит), окно за пределами экрана. Закрывать его вручную не нужно.
4. **Transmission** хранит пароль RPC в своём keychain, поэтому его нужно
   вписать в `.env` (`TRANSMISSION_USERNAME`, `TRANSMISSION_PASSWORD`) или в
   «Доступы». При смене пароля — там же.
5. Сайт слушает `0.0.0.0` и проброшен наружу: держите `SITE_PASSWORD`
   заполненным.
6. **Не коммитьте `.env`.** В нём ключ модели, пароли трекера и RPC. Файл уже
   в `.gitignore`; в репозиторий попадает только шаблон `.env.example` с
   пустыми значениями и без адресов вашей сети.
7. **Удалённые загрузки уходят в корзину.** Transmission на macOS при удалении
   раздачи с данными перемещает файлы в `.Trashes` на том же диске, а не стирает.
   Место освобождается только после очистки корзины (Finder → «Очистить корзину»).
8. **Правка `.env` требует перезапуска** (`scripts/run.sh restart`): настройки
   читаются один раз при старте. Логины и пароли kinozal/Transmission — другое
   дело, их можно менять на ходу через «Доступы».
